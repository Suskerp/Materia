# Materia engineering review — 1 July to 26 August 2026

Three independent read-only reviews covered architecture/runtime behaviour,
Material 3 conformance, and Home Assistant configuration UX. The reviewed
range contains roughly 44k inserted lines across 148 files.

## Remediation status — 27 August 2026

The release-blocking findings have been addressed locally:

- `npm run check` now syntax-checks the source, enforces one package version,
  runs focused tests, creates the production build and enforces raw/gzip bundle
  budgets. The same gate runs in GitHub Actions.
- HA service calls return explicit success/failure results. Scheduler writes,
  grouped toggles, deletes and native time inputs await those results; editors
  remain open and optimistic values are bounded or rolled back on failure.
- Alarm codes are no longer read from or written to Lovelace config. Legacy
  values are ignored, clearly reported and removed on the next intentional
  edit; code-required operations hand off to Home Assistant's native dialog.
- Counter days use local calendar boundaries and seed the value in effect at
  midnight. Tests cover zero-movement days and the Brussels DST transition.
- Core buttons and connected groups now install their own motion tokens, use a
  separate per-size pressed shape, retain 48 px interaction targets, expose
  native disabled/toggle semantics and have visible keyboard focus. Tabs,
  split menus and expanders now implement their expected keyboard semantics.
- Failing custom colour pairs meet WCAG AA and are protected by a contrast
  test. Reduced-motion tokens now also cover separately consumed durations and
  easings.
- Forecast cards expose loading, unavailable and unsupported states and retry
  failed subscriptions. Media progress re-observes after reattachment. Smooth
  clocks mutate only stable SVG geometry per frame and pause while hidden.
- Editor defaults are render-only until deliberately changed, sections use
  progressive disclosure, and every shared runtime translation is tested for
  both English and Dutch copy.

Two larger optimisations remain deliberately separate from this safety pass:
code-splitting the public card catalogue and replacing per-instance
history/forecast subscriptions with shared reference-counted brokers. Both
change loading/lifecycle architecture across most public elements and should be
profiled and released independently rather than folded into correctness fixes.

## P0 — address before calling the library stable

1. **Add an automated quality gate.** There are no test, lint, typecheck, CI,
   accessibility, contrast, or bundle-budget scripts despite safety-sensitive
   alarm, lock and scheduler code. Start with payload/date tests, action failure
   rollback, keyboard semantics, i18n parity, contrast, and a production build.
2. **Make service success truthful.** `src/utils/action-handler.js` currently
   catches service errors without returning a failing result. Several cards can
   therefore close or retain optimistic state after a rejected call. Await
   mutations, keep forms open on failure, and bound optimistic pins with retry
   or rollback.
3. **Remove alarm codes from dashboard configuration.** Masked input is still
   plaintext Lovelace storage. Delegate authorization to Home Assistant or a
   protected helper/integration instead.
4. **Fix core button motion plumbing.** `materia-button` and split-button use
   motion custom properties without installing their own motion tokens. Their
   square resting and pressed shapes also share one radius, preventing the M3
   pressed morph for square buttons.

## P1 — correctness, performance and usability

- Daily cumulative history deltas omit the state at local midnight and use
  fixed 24-hour increments, causing wrong values and DST errors
  (`src/utils/history.js`). Prefer HA statistics for `total_increasing`, or seed
  every local-day boundary with the preceding state.
- Package, runtime and Git tag versions have diverged. Use one version source
  and fail the build when they disagree.
- The full ~920 KB bundle and every editor load eagerly. Split or lazy-load
  uncommon card families; avoid runtime Google font requests.
- Most components rerender for every global `hass` update. Add entity-aware
  update guards and shared/ref-counted history and forecast subscriptions.
- The smooth clock performs a full Lit render at 60 fps. Update stable SVG
  transforms directly and pause while hidden.
- Media progress does not recreate its ResizeObserver after reattachment.
- Scheduler defaults previously invented `turn_on/turn_off` for every domain.
  Require explicit actions where Home Assistant has no safe domain default.
- Editor configuration is too raw in several cards. Put service names, object
  schemas, entity IDs and Browser Mod plumbing in collapsed Advanced sections;
  use managed repeaters and plain-language previews for normal configuration.
- Standardize stable loading, unavailable, empty and retry states instead of
  silently removing failed weather/history cards.

## M3 and accessibility

- Preserve a minimum 48×48 interaction target around visual XS/S controls.
- Add native disabled semantics, `aria-pressed`/`aria-checked`, focus-visible
  states, accessible icon-only labels, and complete keyboard navigation.
- Use separate per-size round, square and pressed shape tokens; selected toggle
  shape remains the inverse of its configured resting shape.
- Replace raw durations/easings with the shared effects/spatial motion tokens
  and cover every decorative/continuous animation with reduced-motion rules.
- Two light-theme custom pairs fail normal-text contrast: `climate-cool` and
  `warning`. Regenerate their on-colours and add an automated contrast check.
- `materia-chips` currently behaves like toggle buttons rather than M3 chips;
  either implement chip anatomy or rename/delegate it to button-group.
- `materia-tabs` exposes tab semantics but deliberately draws a connected
  button group. Split the two concepts or align semantics and visuals.

## Strong foundations

- Most complex cards carefully clean subscriptions, timers and gesture state.
- Template rendering correctly uses authenticated WebSocket subscriptions.
- Media progress and the climate dial demonstrate the preferred narrow direct-
  DOM animation pattern.
- The centralized EN/NL runtime translation layer is a good base.
- Newer code generally uses semantic colour roles and declarative HA actions.

## Recommended order

1. Tests/CI and truthful service results.
2. Alarm-secret removal and action/keyboard accessibility.
3. Core motion/shape/contrast tokens.
4. History correctness and subscription deduplication.
5. Editor progressive disclosure and complete i18n.
6. Bundle splitting, render guards, version/docs automation.
